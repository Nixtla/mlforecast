---
title: Transfer Conformal Prediction Intervals
---

This tutorial evaluates the **conformal prediction transfer methods**
available in `mlforecast`. We train a model on one domain (M4 Monthly
**Macro** series) and then generate calibrated prediction intervals for
a different domain (M4 Monthly **Finance** series) — without retraining
the model.

## Why transfer?

Standard conformal prediction intervals are calibrated on the same
distribution as training data. When you apply a pretrained model to
**new, unseen series** from a potentially different domain, the source
conformity scores may be miscalibrated for the target domain. Transfer
conformal methods attempt to correct for this shift using different
strategies:

| Method           | Strategy                                                              | Needs CV on target? |
|------------------------|------------------------|------------------------|
| `Recalibration`  | Re-run cross-validation on target data                                | Yes                 |
| `ScaleAlignment` | Rescale source errors by target/source scale ratio (from *y* history) | No                  |
| `ErrorScaling`   | Rescale source errors by target/source prediction error ratio         | Yes                 |

We evaluate each method’s **empirical coverage** — the fraction of test
observations that fall inside the predicted interval — and compare it to
the nominal level.

## Load M4 Monthly Data

The M4 Monthly dataset contains 48,000 monthly time series across 6
categories. We use it to create a cross-domain transfer scenario:

-   **Source domain**: `Macro` category — macroeconomic time series
-   **Target domain**: `Finance` category — financial time series

The forecast horizon for M4 Monthly is **h = 18** months.

```python
HORIZON = 18
DATA_DIR = '../../../data'

def read_and_melt(file):
```

## Fit MLForecast on Source Domain

### Feature engineering for cross-domain transfer

Because the model is trained on one domain and applied to another, the
features must be **scale-invariant**. Tree models cannot extrapolate: if
a Finance series has level changes larger than anything seen in the
Macro training data, its predictions get clamped to the training range,
producing large, skewed errors that no conformal correction can fully
repair.

We therefore model **log-returns** instead of raw differences:

-   `GlobalSklearnTransformer(FunctionTransformer(np.log1p, np.expm1))`
    followed by `Differences([1])` — the model sees relative changes,
    which live on a comparable scale in both domains. Back-transformed
    intervals scale multiplicatively with each series’ level.
-   Volatility and trend features (`RollingStd`,
    `ExponentiallyWeightedMean`, `SeasonalRollingMean`) — these sharpen
    the point forecasts.

### Prediction interval configuration

`PredictionIntervals` only calibrates the intervals of the Macro series.
The transfer method is chosen when transferring:
`mlf.transfer(df, method)`, where `method` is a `Recalibration`,
`ErrorScaling` or `ScaleAlignment` instance holding the method’s options
(the backtest `n_windows` and `step_size` for `Recalibration` and
`ErrorScaling`, and the `scale_estimator` for `ScaleAlignment`, which
defaults to the MAD of first differences).

`Recalibration` only uses the target backtest, so it also works on a
model fit without `prediction_intervals` when given
`Recalibration(h=...)`. `ErrorScaling` and `ScaleAlignment` reuse the
source conformity scores and need them at fit.

```python
def fit_source():
    mlf = MLForecast(
        models=lgb.LGBMRegressor(n_estimators=100, verbosity=-1, random_state=0),
        freq=1,
        lags=[1, 2, 3, 4, 6, 12],
        lag_transforms={
            1: [
                ExpandingMean(),
                RollingMean(window_size=3),
                RollingStd(window_size=12, min_samples=6),
                ExponentiallyWeightedMean(alpha=0.3),
            ],
            12: [SeasonalRollingMean(season_length=12, window_size=2, min_samples=1)],
        },
        target_transforms=[
            GlobalSklearnTransformer(FunctionTransformer(func=np.log1p, inverse_func=np.expm1)),
            Differences([1]),
        ],
        num_threads=1,
    )
    return mlf.fit(
        source_train,
        prediction_intervals=PredictionIntervals(
            n_windows=2,
            h=HORIZON,
            method='conformal_error',
        ),
    )
```

## Evaluate Transfer Methods

We fit once on the source domain and, for each transfer method, call
`mlf.transfer(target_train, method)` to get a forecaster for the target
domain (Finance series), and then its `predict` method with
`level=[80, 90, 95]`. `transfer` adapts the conformity scores to
`target_train`, so `predict` only reads them.

We then merge predictions with `target_test` and compute the **empirical
coverage** at each level.

```python
LEVELS = [80, 90, 95]
MODEL = 'LGBMRegressor'

transfer_methods = {
    'Recalibration': Recalibration(),
    'ScaleAlignment': ScaleAlignment(),
    'ErrorScaling': ErrorScaling(),
}

source_model = fit_source()
preds_by_method = {}
coverage_results = {}

for name, method in transfer_methods.items():
    print(f"Running {name}...", end=' ', flush=True)
    preds = source_model.transfer(target_train, method).predict(
        h=HORIZON, level=LEVELS
    )
    preds_by_method[name] = preds
    merged = target_test.merge(preds, on=['unique_id', 'ds'])
    cov = {}
    for lv in LEVELS:
        lo_col = f'{MODEL}-lo-{lv}'
        hi_col = f'{MODEL}-hi-{lv}'
        covered = (merged['y'] >= merged[lo_col]) & (merged['y'] <= merged[hi_col])
        cov[lv] = float(covered.mean())
    coverage_results[name] = cov
    print(f"done. Coverage: { {k: f'{v:.1%}' for k,v in cov.items()} }")

print("\nAll methods evaluated.")
```

## Interval Width Analysis

Beyond coverage, we also care about interval sharpness. Narrower
intervals (lower width) are better, as long as coverage is maintained.

```python
width_results = {}

for method, preds in preds_by_method.items():
    widths = {}
    for lv in LEVELS:
        lo_col = f'{MODEL}-lo-{lv}'
        hi_col = f'{MODEL}-hi-{lv}'
        width = (preds[hi_col] - preds[lo_col]).mean()
        widths[lv] = float(width)
    width_results[method] = widths

width_df = pd.DataFrame(width_results).T
width_df.columns = [f'{lv}%' for lv in LEVELS]
print("Mean interval width by method and level:")
print(width_df.round(2).to_string())
```

## Summary

The table and charts above show how each transfer method calibrates
prediction intervals when moving from a Macro source domain to a Finance
target domain in M4 Monthly data.

**Key takeaways:**

-   **Feature engineering matters as much as the transfer method.**
    Modeling log-returns (`log1p` + `Differences([1])`) instead of raw
    differences makes the features scale-invariant across domains and
    removes the systematic point-forecast bias. With raw differences,
    every method under-covers by a wider margin.
-   `Recalibration` backtests the trained models on the target data and
    uses those residuals — it tends to be the most directly calibrated
    but requires enough target history for the backtest windows (no
    model is retrained).
-   `ScaleAlignment` uses the scale of the *y* signal (MAD of
    differences) to align source residuals — zero-shot, no CV needed.
-   `ErrorScaling` runs CV on the target data to estimate prediction
    error magnitude — a middle ground between full recalibration and
    scale alignment.
-   All three methods under-cover by 2–4 percentage points here. Pooling
    conformity scores across heterogeneous series makes intervals too
    wide for calm series and too narrow for volatile ones; the
    per-series scaling of `ScaleAlignment` targets this, at the cost of
    wider intervals.

The right method to use depends on your constraints: - If you can run CV
on the target: `Recalibration` or `ErrorScaling` - If you need zero-shot
transfer: `ScaleAlignment`
